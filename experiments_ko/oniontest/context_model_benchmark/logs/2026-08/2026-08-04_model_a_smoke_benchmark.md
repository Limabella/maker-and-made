## 발견한 문제

1. 허용 라벨을 프롬프트에 제시해도 `emotion=["apology"]`처럼 필드 간 라벨을 혼동했다.
2. `emotion=[]`를 출력해 스키마의 `minItems: 1` 조건을 두 번 위반했다.
3. 일반적인 불안 표현은 `caution`으로 과대 분류하면서 `사라지고 싶다`는 표현은 `none`으로 분류했다. 안전 신호의 일관성이 부족하다.
4. 관계 신호를 `distancing`으로 치우쳐 예측했다.
5. `MND-007`은 이전 문맥 없이 “계획을 실행한다”는 문장만 제공되어 자해 계획인지 알 수 없다. 모델 오류와 데이터 오류를 분리하기 위해 사례를 수정해야 한다.
6. OpenAI 호환 `/v1/chat/completions`와 Ollama 네이티브 `/api/chat`에 전체 공통 프롬프트를 전달한 호출이 완료되지 않았다. 이번 실행은 정상 동작하는 Ollama CLI를 사용했다.

## 판단

Model A는 현재 조건에서 속도와 JSON 파싱 안정성은 양호하지만, 스키마 준수와 안전 신호 분류가 MND-N 적용 기준에 미달한다. 현재 결과만으로 채택하지 않고 Model B와 Model C를 같은 사례와 조건으로 실행한 뒤 비교한다.
